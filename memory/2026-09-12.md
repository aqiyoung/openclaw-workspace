## 模型实时切换卡住（2026-09-12）

**现象**：主会话切换模型后，`session_status` 长期显示 `live switch pending`，实际模型反复回到默认值，Telegram/app 无法正常切换。

**排查结论**：provider、API key、模型目录和 fallback 链均正常；问题发生在 2026.9.3 的会话级实时切换状态。旧主会话与活跃 run/steer 并发时，切换被标记为 pending，但没在干净的运行时边界完成并清除标志。

**修复**：用户已批准更新命令成功完成（exit 0），Gateway 重启到 OpenClaw 2026.9.4。重启后 `live switch pending` 消失，当前会话正常运行 `openrouter/nex-agi/nex-n2.5-pro:free`，配置的默认模型仍为 `sensenova/deepseek-v4-flash`。

**经验**：
- 先区分“全局默认模型”“会话模型 pin”和“当前实际运行模型”。
- `live switch pending` 长期不消失时，优先检查旧会话/活跃 run 和 Gateway 版本，不要反复删 provider/auth。
- 2026.9.4 的模型选择与并发 session reconciliation 修复覆盖此类问题。
