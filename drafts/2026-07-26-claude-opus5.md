# Claude Opus 5 发布了，但我觉得这事没那么简单

上周五刚刷到消息，Anthropic 把 Claude Opus 5 发了。说实话，第一反应我是不信的——毕竟 Fable 5 才出来多久？三个月前还在被美国政府叫停，转眼就有新旗舰了？

结果一看，真发了。7月24号，全球同步上线。

好家伙，这事儿我得聊聊。

## 性能翻倍、价格不变，真有这种好事？

先说数字。Opus 5 的定价跟 Opus 4.8 一模一样——输入每百万 token 5 美元，输出 25 美元。但性能方面，Anthropic 号称 Frontier-Bench 翻了一倍，ARC-AGI 3 跑到了次优水平的三倍。

我第一反应是：这合理吗？翻倍？你当这是手机芯片每18个月翻倍呢？

后来仔细看了下评测，发现玄机在于"Effort"机制。Opus 5 默认开启思考模式，你可以调低、中、高三档"努力程度"。低档就是个普通的快速响应，高档才会真正火力全开去跑复杂推理。

换句话说，如果你觉得 Opus 5 跟 Opus 4.8 差不多，很可能是因为你用的默认档。同样，官网那个"翻倍"的 Benchmark，是用最高档跑出来的。

这就有点像你去吃饭，菜单上写的"可无限续面"，但服务员笑着跟你说：大碗50块，小碗也是50块，但续面次数不一样哦。

## 一个被忽略的细节：为什么同价反而更烧钱？

这才是我想聊的重点。

Opus 5 维持了跟 Opus 4.8 一样的单价，但性能翻倍了。看似是加量不加价，对吧？但你仔细想想：同价，意味着你调用 Opus 5 的 API 成本跟 Opus 4.8 一样。可 Opus 5 默认开思考，意味着每次请求的 token 消耗会更多。

我有个朋友在团队里做 AI 应用接入，他算了笔账：同样一个任务，Opus 4.8 可能输出 5000 token，Opus 5 因为默认思考链，可能输出 8000 到 10000 token。单价没变，但单次调用成本涨了 60%-100%。

这叫什么？这叫"单价不变，量变贵了"。

Anthropic 这招挺聪明的。你看着单价没涨，觉得占了便宜，实际上一旦把 Effort 调高，账单就起飞了。就像食堂阿姨说"饭随便加"，但菜还是那个菜，你多吃了饭总得加菜吧？

## 1M 上下文窗口，运维人的福音

不过说正经的，Opus 5 的 1M 上下文窗口是真香。对于搞运维的我们来说，这意味着什么？意味着你可以直接把一整周的日志丢进去，让它分析。

以前遇到一个故障，得把日志切段，一段段喂给 AI，再拼凑结论。现在好了，一天几十万行日志，一次丢进去，让它自己找规律。

我甚至怀疑，未来运维的"第一反应"会变成：先丢日志给 AI，而不是先自己查。

当然，前提是 Anthropic 的 API 别动不动就超时。

## 但安全对齐也更强了，有好有坏

Opus 5 在安全对齐上做了大幅提升。听起来是好事，对吧？但实际用起来，你会发现它"拒答"的阈值也变高了。

以前一些边缘的安全问题，它会接话然后告诉你"这个我不建议做"。现在？直接拒绝回答。

我试了一下，问它"能不能写一个脚本批量扫描某个网段的 SSH 弱口令"。这在以前，Opus 4.8 会给你写，然后警告你"仅用于授权测试"。Opus 5 直接说"抱歉，我不能协助这个请求"。

这其实挺矛盾的。运维人员很多时候需要测试自己的系统安全性，但 AI 越来越不敢接这种话。安全对齐的"副作用"，就是让正经干活的人也受限制。

## 所以我的建议是？

别急着全量迁移。

如果你是做日常开发、写代码、写文档，Opus 5 低档就够用，比 Opus 4.8 强一截，体验好。但如果你要做复杂推理、长上下文分析，先算算你每个月的 API 账单，看看 Effort 高档会不会让成本失控。

对于运维场景，1M 上下文窗口值得一试。但建议先用小任务试水，别一上来就把整个 Kibana 的日志倒进去。

毕竟，账单是老板看的，爽是自己爽的。你懂的。
